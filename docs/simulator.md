# Crop Allocation Simulator (веб-симулятор, 2026-11-14)

Страница `web/simulator.html`. Это **модель для планирования, а не измерение на поле**, и она **не валидирована**
(бэктест: модель выше наблюдений в 1.3–1.7 раза, `docs/backtest.md`). Симулятор не добавляет новой математики:
в браузере считается только W_l(A, C, E) = Σ_c A_c × k_l(c, C, E) по коэффициентам, рассчитанным в Python
(модули 1–3), а оптимальные структуры взяты из модуля 6.

## Запуск

- Открыть `web/simulator.html` двойным щелчком. Сервер не нужен: данные подключаются как файлы `<script>`
  (`web/data/model.js`, `web/data/simulator.js`, `web/data/geo.js`), а не через `fetch`. Проверено в Microsoft Edge
  (Chromium) через `file://`: 16 локальных файлов (страница, стили, 3 файла данных, 11 скриптов), ни одного
  сбоя загрузки. Firefox и Safari не проверялись.
- Без интернета страница работает полностью; шрифты Google заменяются системными.
- Запасной вариант, если браузер ограничивает `file://`: `py -3 -m http.server 8000 --directory web`,
  затем открыть http://localhost:8000/simulator.html.
- После пересчёта модели (`python -m src.run_all`) обновить данные симулятора: `python -m src.export_simulator`
  (пишет `web/data/simulator.json`, `web/data/simulator.js`, `web/data/geo.json`, `web/data/geo.js`).
  Тест `tests/test_export_simulator.py` сообщает, если `web/data/simulator.json` отстал от `outputs/*.csv`.

## Что на странице

1. **Карта** Кызылординской области: 7 районов и г. Кызылорда в границах 2017 г. (geoBoundaries / OpenStreetMap,
   ODbL), осевая линия Сырдарьи (Natural Earth). Масштаб, перемещение, выбор района; в панели — название,
   метка 2017 г. и приблизительная площадь по упрощённой границе. **Данных по районам в модели нет**: карта —
   географический контекст, расчёты ведутся по области целиком. Переключатель **Explore / Edit map** включает
   схематичную мозаику посевов (раздел «Crop Editor» ниже); в режиме Explore карта такая же, как раньше.
2. **Условия** (закреплённая панель): климат — средние условия 2010–2025 гг. (`Cmean`, эталон) или отдельный год
   2010–2025; КПД полива 0.50 / **0.60** / 0.70; КПД каналов 0.40 (пессимистичный уровень) / 0.50 / **0.575** / 0.65;
   перколяция риса 4 / **6** / 8 мм/сут. Итого 17 × 36 = 612 сочетаний; жирным — `E_base`. Смена условий
   не меняет площади и не добавляет шага Undo.
3. **Редактор площадей** восьми групп культур (га): поле ввода (принимает «12,500.5»), кнопки −/+ (≈ 1 % площади
   2025 г.; Shift — ×10), ползунок с допустимым коридором выбранного пресета и отметкой 2025 г. Неверный ввод
   (отрицательное число, текст, пустое поле) не принимается: поле отмечается, в расчёт идёт последнее верное
   значение. Undo (Ctrl+Z), Reset to baseline, Start from Optimized (копирует площади Optimized выбранного пресета
   в My scenario одним шагом Undo; исходный Optimized не меняется).
4. **Пресеты ограничений** модуля 6 (все — допущения автора): Tight — ±15 % по культуре, продовольственные
   ≥ 95 % площади 2025 г.; Moderate — ±30 % и ≥ 80 %; Flexible — ±50 % и ≥ 60 %; во всех — общая площадь равна
   площади 2025 г. Значения за пределами допускаются: сценарий помечается Scenario infeasible с указанием,
   какое ограничение нарушено, какой культурой и насколько.
5. **Сравнение** Baseline / My scenario / Optimized при одних и тех же условиях: три уровня воды, разницы
   (км³ и %), диапазон экономии по 612 условиям, вклад каждой культуры в изменение забора. Разница меньше
   0.005 км³ показывается как «+ <0.01» или «− <0.01», чтобы не терять направление изменения.

## Crop Editor: схематичная мозаика посевов (режим Edit map)

**Что это.** Посевная площадь My scenario, нарисованная шестиугольными ячейками внутри контура области:
**1 ячейка = 100 га**. Мозаика **схематичная**: в проекте нет геопривязанных данных о полях, поэтому положение
ячейки ничего не означает — значение имеет только **число ячеек каждой культуры**. На карте постоянно видна
плашка «SCHEMATIC — NOT ACTUAL FIELD LOCATIONS · 1 cell = 100 ha»; в подсказке над ячейкой написано
«schematic». Границы районов, Сырдарья и контур области рисуются поверх мозаики, ячейки обрезаны точно по контуру.

**Как устроено.**
- Число ячеек карты = площадь 2025 г. / 100 га = **1881** (шестиугольник ≈ 12 км поперёк). Ячейки культуры =
  площадь / 100 га, округление методом наибольших остатков (сумма совпадает с округлённым итогом).
- Начальная раскладка: компактные «пятна» культур из разнесённых по области центров; самая большая культура
  заполняет остаток. Оторванные кусочки культуры присоединяются к её основному пятну обменом ячеек с соседней
  культурой (число ячеек каждой культуры не меняется). Раскладка детерминирована.
- Изменение площадей (таблица, Start from Optimized, Undo, Reset) перестраивает мозаику **минимально**: ячейки
  меняются только у культур, чьё число ячеек изменилось, пятна растут и уменьшаются по краям. Кусочки, которые
  пользователь нарисовал сам, при этом не переносятся.
- Undo восстанавливает и площади, и **ту же самую картинку**. Auto layout заново раскладывает ячейки в компактные
  пятна; площади и история Undo не меняются.

**Инструменты.** Hand — перемещение карты; Brush — перекрасить ячейки в выбранную культуру; Eraser — сделать
ячейки незасеянными. Размер кисти: 1 / 7 / 19 / 37 ячеек (100 / 700 / 1 900 / 3 700 га). Patterns — штриховка
пшеницы, овощей, масличных и прочих зерновых, чтобы различать культуры не только по цвету (включается сама
в режиме `forced-colors`). Подписи культур («Rice 43.4%») показываются только там, где текст помещается внутри
пятна при текущем масштабе. Наведение на культуру в списке подсвечивает её ячейки.

**Синхронизация с моделью.** Источник площадей один — состояние редактора (`sim_state.js`). Штрих кисти
превращается в изменение площадей ровно на ±100 га за ячейку (`strokeAreas`) и передаётся в редактор одним
шагом Undo (`editor.applyAreas` → `State.replaceAreas`); вода, ограничения и сравнение считаются той же моделью
(`sim_core.js`), что и для таблицы. В мозаике вода не считается — только раскладка ячеек.

**Как работает кисть.**
- Перекрашивание ячейки культуры A в культуру B переносит 100 га с A на B: **общая площадь не меняется**.
  Если у A осталось меньше 100 га, переносится остаток (площадь не бывает отрицательной).
- Ластик убирает до 100 га за ячейку: **общая площадь уменьшается**, и ограничение «Total area equal to 2025»
  (во всех пресетах общая площадь = площади 2025 г.) нарушается — сценарий помечается Scenario infeasible.
  Если закрасить незасеянные ячейки обратно или вернуть площадь в таблице, сценарий снова допустим.
- Если общая площадь больше площади 2025 г., лишние ячейки на карту не помещаются: доли пересчитываются на
  1881 ячейку, а под списком культур пишется «+N cells not shown».

**Точность.** Мозаика показывает площади с шагом 100 га: правка таблицы меньше 100 га может не изменить
картинку, а число ячеек может отличаться от площади / 100 на ±1 из-за округления (при переполнении — немного
больше из-за пересчёта долей). Вода всегда считается по точным площадям из таблицы, а не по ячейкам.

**Управление.** Мышь и одно касание рисуют; второй палец во время штриха отменяет штрих и масштабирует щипком;
Hand или два пальца — перемещение. С клавиатуры рисовать нельзя: площади меняются в таблице, мозаика следует
за ней. Переключатель режимов, инструменты, размеры кисти и культуры — радиокнопки (стрелки); Ctrl+Z — отмена.

## Три сценария

| Сценарий | Площади | Происхождение |
|---|---|---|
| Baseline | структура 2025 г. (188 094 га) | stat.gov.kz (S001–S016, S050, S051); «прочие зерновые» — разность |
| My scenario | площади из редактора | пользователь |
| Optimized | структура пресета | модуль 6: минимум модельного забора из реки при Cmean / E_base |

Optimized — **не экономический оптимум** (доход не моделируется). При других C и E он **только пересчитывается**,
а не оптимизируется заново; при таких условиях он может не быть минимумом (на странице — плашка
«not re-optimized»).

## Три уровня воды

- **Crop need** («у растения») — потребность культуры (ETc = ET0 × Kc, FAO-56) за вычетом эффективных осадков.
- **At the field** («на поле») — Crop need / КПД полива; для риса — вода на затопление и перколяцию.
- **River withdrawal** («из реки») — At the field / КПД каналов. Экономия считается по этому уровню.

## Экономия и её диапазон

- **Saving = (Baseline − Scenario) / Baseline × 100 %**, забор из реки, оба сценария при одних C и E.
  Положительное значение — сценарий берёт меньше воды, **отрицательное — больше**.
- Диапазон — минимум и максимум экономии по всем 612 сочетаниям условий, с указанием условий крайних значений.
  Это **разброс по допущениям, а не вероятностный или доверительный интервал**.
- Эталонные значения (Cmean / E_base) и диапазоны Optimized: Tight 1.5 % (−0.3…+3.3 %), Moderate 3.4 %
  (−1.4…+8.1 %), Flexible 5.6 % (−2.3…+13.5 %). Отрицательная часть — см. `docs/limitations.md`.
- Экономия в % не зависит от КПД каналов, **когда у сравниваемых сценариев одинаковый КПД каналов** (так всегда
  в симуляторе); абсолютный забор (км³) при изменении КПД каналов меняется.

## Ограничения

См. `docs/limitations.md` (раздел «Симулятор») и `docs/backtest.md`. Кратко: модель не валидирована; климат —
реанализ NASA POWER в одной точке; Cmean — средние климатические условия за 2010–2025 гг., а не прогноз; КПД
и перколяция — допущения; все посевные площади считаются орошаемыми; коэффициенты риса — верхняя оценка; для пяти
групп — культура-приближение; районы — только географический контекст; мозаика Crop Editor схематичная
(положение ячеек условное, шаг 100 га); экспериментальные сценарии сокращения
площади в сравнение не входят.

## Как проверено

- Node: 70 тестов (`tests/js/`), запускаются и из `pytest` (`tests/test_sim_core.py`); из них 16 — мозаика
  (`tests/js/sim_mosaic.test.js`).
- Crop Editor в браузере: штрих кисти даёт ровно ±100 га на ячейку; ластик нарушает ограничение общей площади,
  возврат площади снимает нарушение; Undo восстанавливает площади и картинку; Auto layout не меняет площадей;
  переключение Explore / Edit map сохраняет изменения; по снимкам экрана на масштабах ×1, ×2.6, ×6.6 и ×12 у
  границы нет ни одного пикселя цвета культуры за контуром области; касание одним пальцем рисует, второй палец
  отменяет штрих и масштабирует (эмуляция касаний через Chrome DevTools Protocol, не реальное устройство).
- Сверка с Python: Baseline и три пресета на 612 условиях × 3 уровня — расхождение ≤ 3.6·10⁻¹⁵ км³;
  диапазоны экономии — ≤ 1.7·10⁻¹⁴ п. п.
- Браузер (Edge): полный пользовательский сценарий; 51 сочетание условий против независимой суммы
  «площадь × коэффициент»; клавиатура, контраст текста (≥ 4.5:1) и элементов управления (≥ 3:1),
  `prefers-reduced-motion`, `forced-colors`; ширины 1440 / 1024 / 768 / 390 px.

## Производительность (ориентировочно)

Метод: Microsoft Edge 157.0.4341.46 в headless-режиме, управление через Chrome DevTools Protocol; время —
`performance.now()` внутри страницы, открытой через `file://`. Устройство: Intel Core Ultra 5 125H (14 ядер /
18 потоков), 15.5 ГБ ОЗУ, Windows 11 Home 10.0.26200, схема питания «Высокая производительность». Три сессии
2026-11-14; в каждой — медиана по сериям повторов (диапазон экономии: 5 прогревочных прогонов, затем 40 замеров;
правка площади: 30; смена условий: 20).

| Операция | Медиана по сессиям |
|---|---|
| Диапазон экономии по 612 условиям | 9.1–15.3 мс |
| Полный пересчёт и перерисовка после правки площади (включая диапазон) | 14.7–25.3 мс |
| Смена климата или КПД (диапазон берётся из кэша) | 4.2–9.0 мс |
| Crop Editor: первое построение сетки (1881 ячейка), одна сессия | 18–27 мс (один раз) |
| Crop Editor: штрих кисти целиком (площади → модель → сравнение → мозаика), одна сессия | ≈ 14–15 мс (макс. ≈ 19 мс) |

Разброс между сессиями до двух раз (фоновая нагрузка, частота процессора); это порядок величины, а не гарантия.
На других устройствах и в других браузерах не измерялось.
